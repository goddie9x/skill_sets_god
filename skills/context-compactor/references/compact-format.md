# Compact format — CONTEXT-COMPACT.md

One file, project root, gitignored. Eight sections, always in this
order (the `check` subcommand enforces the headings):

1. **Goal** — what the user wants, in their terms. 1–2 sentences.
2. **Decisions (verbatim)** — every decision that constrains future
   work, with the chosen option. Quote the user's wording when the
   wording itself is the decision ("max 10 loops, then report").
3. **Open tasks** — checkbox list, each with its current state
   ("deploy #3 READY, waiting user verify"), never just a task name.
4. **Next step** — the single next action, concrete enough to start
   with zero questions.
5. **File map** — generated by `context_compact.py filemap`, then
   purpose filled in by the agent. Only files relevant to the work;
   prune library/build directories (the script already skips them).
6. **User preferences and corrections (verbatim)** — standing rules for
   this work, quoted. A correction recorded here is never needed twice.
7. **Errors and evidence** — current blockers only: exact error,
   producing command, what was tried, result. Logs enter crushed via
   `crush-log`, never raw.
8. **Session state** — declared max context, estimated usage at compact
   time, compact count, timestamp, and one history line per finished
   chunk of work.

## Size discipline

- Target: the whole file under ~10% of declared max context.
- If section 5 or 7 pushes past that, they are too detailed: file map
  is one line per file, errors keep the message and one line of context.
- Finished work compresses hardest: a day of work is often 5 history
  lines. The detail lives in git, not here.

## Worked mini-example

Source: a 640-line deploy log + a 40-message conversation + 3 source
files (~9,300 tokens estimated).

Compact result (~450 tokens, check PASS, 19.8% of sources kept — and
the sources included the raw log; against the conversation alone the
ratio is far lower):

- Goal: 1 sentence.
- Decisions: "purge cache after every deploy" (verbatim user rule).
- Errors: crushed log — 652 lines → repeated lines with counts, 3 unique
  error lines verbatim, head/tail 20. The one real error
  (`address in use`, port 3100) survived word-for-word.
- File map: 3 rows from `filemap` with symbols extracted by the parser,
  not by the agent's memory.

## Tool notes

- No network, no dependencies: Python 3 stdlib only. `tiktoken` is used
  automatically if present, for a real count instead of `chars/4`.
- `measure` exit codes: 0 = under threshold (or no max given),
  10 = compact now, 2 = nothing to measure. Scripts and hooks can gate
  on exit code 10.
- `check` exit codes: 0 = PASS, 1 = FAIL (missing section or fact).
- `init` never overwrites an existing compact file without `--force`:
  an old compact is evidence, not scratch.
